
## Cause en deux temps

1. **Réversion** : une édition récente de `savoir_complet.py` et `__init__.py`
   n'avait pas été suivie d'une sauvegarde. La guérison A232, déclenchée par le
   cycle, a restauré les octets de `courante` — l'état d'avant l'édition — avec
   leur ancien mtime. Le couple restauré était incohérent : nouveau nom exporté,
   ancien module sans ce nom.
2. **Écart perpétuel** : après réparation et nouvelle sauvegarde, les deux
   fichiers d'acte A231 restaient `hash_different`. L'acte était écrit **après**
   la copie, donc la copie contenait toujours l'acte précédent. Corriger
   l'édition seule ne suffisait pas : chaque cycle re-flagait ces deux fichiers.

## Ce que la session a appris

- La copie de soi n'est **pas** une source de vérité pour restaurer une édition
  récente ; elle est par construction en retard.
- Un mtime ancien n'est pas une preuve d'ancienneté du contenu : `copy2`
  l'a recopié.
- Un écart qui réapparaît après chaque sauvegarde indique un bug d'ordre dans le
  sauvegardeur, pas une altération externe.
- Le churn actes/memoire (63 + 62) est le régime normal du dépôt ; le confondre
  avec une régression fait échouer la porte en permanence.
- Après 6 h de suite, 146 écarts non-code ne sont pas une régression : classer
  par zone, rafraîchir la référence, puis rejouer la batterie ciblée.
- Le script de diagnostic doit rester en lecture seule : importer
  `conscience_logique` peut déclencher `verifier_et_guerir`.
