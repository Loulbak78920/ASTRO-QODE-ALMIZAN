# 接管并发出现的重复 Skill

## 目标

在 create 过程中发现另一会话已经生成职责重合的 Skill 时，阻止重复创建，转由用户决策；若选择接管，则以现有磁盘版本为基线完成最小合并、断言实测、最终验收与三方哈希记录。若用户选择“缩窄后新建并存”，按第 2quater 节冻结重合包、只写真实增量并写清委派边界。若接管后用户把交付缩为文档与参考文件，按第 2ter 节保留并发脚本并标为范围外。

## 何时使用

- 目标目录在方案确认后、写入前突然出现，或出现同名、职责重合的 Skill。
- create 命中已有 Skill，需要决定接管、缩窄范围、停止、只读保留、明确分工后并存，还是接管但缩窄交付。
- 用户明确要求接管并完善现有 Skill，而不是再创建一个。
- 目标目录由另一会话创建，用户选择“保持现状”或只要求独立复核、不改写。
- 目标 Skill 自带默认只读门禁，需要区分会写盘的分支并证明零写入。
- 被接管文档包含未经验证的校验器断言，例如围栏块是否豁免、退出码、文件数、引用计数。
- 接管编辑期间文件反复变化，或 QA 结果之后文件又被改写。
- 接管后用户把交付缩为“只写文档和参考文件，不加脚本”，而目标目录已有并发脚本。
- 目标目录不存在，但发现不同名、职责部分重合的 Skill，且其写入者仍活跃。
- 用户选择“缩窄后新建并存”，需要保留真实增量而不是复制重合 Skill。
- 夹具删除报 WinError 5（只读 Git 对象）或 WinError 32（目录被占用），需要如实报告待清理。

不适用于：普通创建与更新规范（`skill-creator`）；一般并发写入机制（`skill-update-concurrency-safe`）；canonical 与 legacy 迁移（`skill-canonical-migration`）；来源证据提取（`audit-session-evidence`）；夹具重放与校验器自测（`replay-skill-reference-fixtures`）；新 Skill 或只改 SKILL.md 的分阶段交付（`skill-staged-delivery`）；纯已安装 Skill 盘点与跨根冲突（`inventory-installed-skills`）；自动推荐数据对账（`verify-skill-recommendation-claims`）。

## 不可协商约束

1. **先停写，再决策。** 发现职责重合时停止创建；不得静默创建第二个 Skill、擅自改名或删除现有 Skill。用户必须在“接管并完善 / 缩窄后新建并存 / 停止创建 / 只读保留 / 明确分工后并存 / 接管但缩窄交付”中作出选择。
2. **create 不覆盖。** 目标存在即转 update；用户选择接管时，原目标目录不得创建，最终报告写“接管”而不是“创建”。
3. **接管以磁盘为基线。** 完整读取现有 SKILL.md、references、脚本与资源；保留仍有效规则；删除、归档、重命名现有 Skill 都需要针对具体路径的明确授权。
4. **双采样后再编辑。** 记录目录内全部文件的 size、mtime、SHA-256；连续三次哈希一致才写入；已知有并发写入时提高阈值或停止。
5. **最小合并。** 优先使用最小 Edit；遇到“file changed since your last read”立即停止，重读当前文件，重新定位后再改；并发新增的标题、计数表述、参考文件与规则必须保留。
6. **断言必须实测。** 文档中关于校验器、退出码、文件数、围栏块、引用计数的断言，必须在 Skill 目录之外用单一变量 A/B 夹具验证；未实测的断言不得写成事实。
7. **错误断言全量纠正。** 同一错误可能出现在约束、事实节、诊断表、证据状态表和完成清单；按唯一短语搜索并同步修正，保留原断言与实测反证，不删除证据。
8. **验证不复用旧 PASS。** 文件每次变化后重跑 `skill-file-qa`；只有稳定指纹上的 `RESULT PASS`、实际计数、文件清单与回读结果才能作为完成依据。
9. **三方哈希可追溯。** 至少记录接管前基线、并发改写时版本、最终接管版本；脚本哈希单独记录，未授权不得变化。
10. **只读保留不写盘。** 用户选择保持现状时，不得创建、编辑、删除或重命名目标目录中的任何文件；只允许默认只读命令与 Skill 目录之外的副作用快照。报告写 KEEP-READ-ONLY，并逐项列出未执行的写盘分支。
11. **缩窄范围不删除并发产物。** 用户把交付缩为文档与参考文件时，保留并发脚本并标为范围外；删除、移动或重命名必须针对具体路径单独授权，并在 Skill 目录之外备份、核对 SHA-256 后才执行。
12. **清理以磁盘状态为准。** 清理失败时记录异常类型、路径与退出码；WinError 5 用可写位或 onexc 重试，WinError 32 等待占用释放；只有 `test -e` 为假才可写“已清理”，否则写“待处理”。
13. **写入者集合是动态的。** 只把 `ready` 当作该会话当前回合结束，不当作“不会再写”；只读核查者可能转为写入者，新写入者也可能出现。每次写入前重扫 JSONL 的成功 Write/Edit 记录；出现新写入者时重新等待、重新采样，旧基线与旧 PASS 作废。
14. **验收片段不写漂移计数。** 验收片段只断言不变量（如退出码、`BASE_OK`）或日期化观测；嵌套 `.git` 数、JSONL 数、顶层项数等随夹具与会话变化的值，不得写成固定契约。
15. **并存必须有边界。** 缩窄后新建只写真实增量；重合职责必须在“什么时候不用”或委派表写清归属，不得复制重合 Skill 的步骤、触发词或夹具。
16. **重合包只读冻结。** 写入前记录重合包全部文件的 size、mtime、SHA-256；写入后重算，任一变化即作废边界与验收。
17. **只归因新目标。** 缩窄后新建的写入者扫描只统计新目标路径；重合包写入者、临时文件写入者与当前会话分列。

## 流程

### 0. 预检与重复检测

1. 确认用户指定的目标目录状态；不存在才进入 create。
2. 按名称、description、触发词、目标、步骤、脚本、references、退出码搜索用户级与项目级 Skill。
3. 在准备写入前再次扫描，因为规划期间可能出现并发创建。
4. 一旦发现同名或职责重合，冻结写入，记录目录首次出现时间与文件 mtime。

### 1. 能力矩阵与用户决策

| 维度 | 现有 Skill | 新目标 | 判定 |
|---|---|---|---|
| 名称与触发词 |  |  | 相同 / 相近 / 不同 |
| 目标与输入输出 |  |  | 重合 / 部分重合 / 不同 |
| 步骤与不变量 |  |  | 可直接复用 / 需合并 / 冲突 |
| 脚本与退出码 |  |  | 相同 / 更完整 / 缺失 |
| references 与证据 |  |  | 可复用 / 需补充 |
| 维护与发布路径 |  |  | 同一 / 不同 |

把矩阵与建议交给用户，至少提供以下选项：

- **接管并完善现有**：不创建新目录；以现有 Skill 为唯一归属。
- **缩窄后新建并存**：目标不存在时保留 create，但只写真实增量，按 2quater 冻结重合包、写清委派边界，并确保触发词不重叠。
- **停止创建**：只记录冲突与证据。
- **只读保留**：用户选择保持现状；不写任何目标文件，只做独立复核并报告。
- **接管但缩窄交付**：以现有 Skill 为归属，但本轮只交付文档与参考文件；保留磁盘上的并发脚本并标为范围外。
- **明确分工后并存**：必须写清两个 Skill 的触发词、输入输出与维护边界。

用户未明确选择前，不写任何目标文件。

### 2. 接管基线

1. 列出并完整读取现有 Skill 的全部文件。
2. 按 2a 建立写入者表并逐个等待；全部 ready 前不编辑。
3. 对 SKILL.md、references、脚本分别记录 size、mtime、SHA-256。
4. 运行现有 `skill-file-qa`，记录真实 PASS、FAIL、WARN、文件清单与指纹。
5. 运行现有脚本的真实正例与至少一个负例，记录退出码；不要只相信文档。
6. 建立“仍有效 / 需修正 / 未验证”清单。

### 2a. 写入者归因与冷却

接管、只读保留、缩窄交付与缩窄后新建共用本节。目标是区分“读过这个 Skill 的会话”和“成功写过它的会话”；缩窄后新建只统计新目标路径，重合包写入者单列（见 2quater 第 4 步）。

1. **扫描写入记录。** 在 `~/.qoder/projects/*/*.jsonl` 中查找目标 Skill 的 `Write`/`Edit` tool_use，并与同一 `tool_use_id` 的 tool_result 配对；失败的 Edit 也会留下 tool_use，只有成功结果才算写入。当前会话单列，不并入他人写入者。
2. **建立写入者表。** 每个写入者记录 sessionId、成功写入次数、首末写入时间、最后写入的文件；与目标文件 mtime 对照。JSONL 时间是 UTC，Windows mtime 是本机偏移（本机为 +01:00），比较前先换算。
3. **列出潜在写入者。** 读取 `list_chat_sessions`，把 `running`/`opening` 的会话列为潜在写入者；该状态不是写入记录，不能据此判断有或无写入，也不能替代 JSONL 配对。每次编辑前重扫 JSONL，确认潜在写入者是否转化为成功写入。
4. **逐个冷却。** 对每个写入者调用 `wait_chat_sessions`，记录 runtimeState、revision 与结果（turn_completed / timeout）；全部 ready 或 waiting-user 后再连续三次采样。
5. **ready 不是终态。** `ready` 只表示该会话当前回合结束；它可以再次变为 running，只读核查者也可能开始写入，还可能出现从未等待过的新写入者。每次编辑前重扫；出现新写入者时回到第 4 步。
6. **验收后重扫。** 最终 QA 后再次扫描写入记录并采样；QA 之后出现成功写入时，旧 PASS 作废，等新写入者 ready 后重跑。
7. **报告写全量。** 报告列出全部写入者、潜在写入者、扫描时刻与未等待的只读会话，不只写“创建者会话”。

### 2bis. 只读保留分支（KEEP-READ-ONLY）

用户选择保持现状，或只要求复核并发创建的目标时，执行本分支并保持零写入。

1. **记录来源。** 写出创建者会话 ID、目标首次出现时间、创建期间的文件 mtime 范围；区分“本会话创建”与“另一会话创建”。
2. **等待稳定。** 按 2a 列出全部写入者并逐个等待；对目录内全部文件记录 size、mtime、SHA-256，要求连续三次一致。任一写入者仍 running 时记录其 revision，并在报告中标“可能继续写入”；`ready` 只代表该回合结束，不代表不会再写。未稳定时不得给出最终结论。
3. **完整读取。** 读取 SKILL.md、references 与 scripts；列出文档中的可观测值，包括计数、哈希、行数、退出码与描述长度。
4. **静态验收。** 用 `py -3` 运行 `skill-file-qa`，记录实际 PASS/FAIL/WARN、`Files (N)`、description 长度、正文行数与引用检查；不复用创建者的旧结果。
5. **默认只读门禁。** 只在目标 Skill 的默认或只读模式下运行其自带门禁；先按 `verifier-effets-de-bord-verification-lecture-seule` 对可能被写入的索引、日志与封条做前后快照。明确不运行会写盘的分支，例如目标脚本的 `run`、`--persist`、`--avec-*`（本机实例：`--avec-tests`、`--avec-regression`、`--avec-run`）；若默认模式本身写盘，先隔离或停止。解释器与编码按 `skill-update-concurrency-safe` 处理：Store 存根可能以 49 退出，非 ASCII 输出需 UTF-8。
6. **核对文档。** 把第 3 步列出的观测值与实际输出逐项对照；不一致时标为“文档漂移”，本分支不静默修正。
7. **报告。** 写 `模式: KEEP-READ-ONLY`、创建者与写入者会话、稳定指纹、双验收结果、未执行分支与重跑条件；任一写入者之后再次写入、只读会话转为写入或出现新写入者时，必须重跑静态验收和门禁。

### 2ter. 缩窄范围的接管

用户决定接管但明确“只写文档和参考文件，不加脚本”时，按本分支执行。

1. **确认边界。** 引用用户原话，列出本轮写入的文件（SKILL.md、references）与不写入的文件（scripts、assets）；并发脚本保留在磁盘上。
2. **基线不变。** 仍按第 2 节记录全部文件哈希，包括范围外脚本；脚本哈希在报告中标“范围外，未验证”。
3. **只改文档。** 不删除、不移动、不改名范围外脚本；文档中删除对范围外脚本的调用与选项引用，避免读者按文档执行不存在的命令。
4. **声明范围。** 在 SKILL.md 增加“交付范围”说明，指出哪些文件存在、哪些在本轮范围外、脚本契约未实测。
5. **保留证据。** 历史证据可以保留，但必须注明“历史证据，当前脚本不在本轮范围”。
6. **验收。** 运行 `skill-file-qa`；`Files (N)` 仍包含范围外文件，不得把 N 改小来伪装交付范围。
7. **后续授权。** 若用户之后要求删除脚本，先在 Skill 目录之外备份并核对 SHA-256，再按授权删除，并重跑 QA 与 manifest。

### 2quater. 缩窄后新建并存（NARROWED-CREATE）

目标不存在，但能力矩阵显示不同名 Skill 已覆盖部分职责，且用户选择“缩窄后新建并存”时，按本分支执行。它不是接管，也不是复制重合 Skill。

1. **锁定真实增量。** 在能力矩阵中逐项标出重合职责与不可替代的增量；只把增量写进新 Skill。把重合职责写成委派，例如 CRLF 与 `autocrlf` 夹具 → `verifier-fixture-autocrlf-non-vacue`，通用 bash 块 → `verify-skill-command-blocks-fixture`，既有夹具重放 → `replay-skill-reference-fixtures`，写入后验收 → `skill-file-qa`，来源取证 → `audit-session-evidence`。在“什么时候不用”或资源表写出这些归属。
2. **冻结重合包。** 对重合目录内全部文件记录 size、mtime、SHA-256（至少 SKILL.md、references、scripts）；不得修改、移动、删除或 `git add` 其中任何文件。其写入者仍 `running` 时标“可能继续写入”，每次写入前重采样。
3. **复查目标。** 写入前用 `test -e` 确认新目标目录仍不存在；出现即停止 create，回到第 1 节重新决策或按 2/2ter 接管。
4. **只归因新目标。** 按 2a 配对 JSONL 的 Write/Edit 与 tool_result，但只统计新目标路径；重合包的写入者、临时文件（如 PR body）的写入者都不计入新目标写入者。当前会话单列；其他会话已写新目标时停止并重判。
5. **最小写入。** 先写 SKILL.md，再写 references；不建脚本、不建空目录，除非增量确实需要。每步写入前重扫第 2 步哈希与第 4 步写入者。
6. **验收与分离哈希。** 用 `py -3` 运行 `skill-file-qa`，要求稳定指纹上的 `RESULT PASS`，记录 `Files (N)`、body、description 与引用检查；分别记录 SKILL.md 与 references 的完整 SHA-256，因为校验器指纹只覆盖 SKILL.md。
7. **证明重合包未变。** 写后重算第 2 步全部哈希；任一变化即说明重合包被并发改写，本 Skill 的边界与委派可能过期：重读、重划边界、重跑第 6 步，不得直接宣称完成。报告写 `NARROWED-CREATE`、重合包前后哈希、委派表、新目标写入者与两个文件哈希。

### 3. 断言实测与纠错

1. 找出文档中可被单条命令否证的断言。
2. 在 Skill 目录之外建立最小 A/B 夹具；两组只差一个变量，frontmatter 的 name 与夹具目录同名。
3. 用同一校验器、同一参数、同一稳定等待时间运行两组，逐字记录输出与退出码。
4. 断言为假时，按唯一短语搜索所有出现位置并同步修正；保留“原断言 / 实测 / 修正位置”三元组。
5. 断言为真时，在证据中标“已复核”，不要为了改写而改写。

### 4. 并发合并

1. 每次编辑前重新采样目标文件，并按 2a 重扫写入记录；哈希变化、出现新写入者或写入者重新 running 时，先等待并重取基线。
2. 只改本次确认的规则；不重排、不顺手整理无关内容。
3. Edit 返回 `0 occurrences found` 时先按并发信号处理：查写入者记录与当前哈希，重读文件并重新定位；确认是 `old_string` 已被并发改写，而不是文本本就不存在。
4. Edit 报文件已变化时，先读当前版本；并发新增内容与本次修改冲突时停止并报告。
5. 修改 SKILL.md 后搜索 references 中的同一规则并同步；新增参考文件必须保留。
6. 校验期间文件再次变化或出现新写入者时，等待稳定并重跑，不复用上一条 PASS。
7. **共享参考文件按尾部合并。** 向 references 追加内容前，重读目标文件最后约 40 行，记录 size、mtime、SHA-256 与尾部锚点；`old_string` 必须取自当前尾部，禁止用旧全文 Write 覆盖。其他会话追加的标题、计数与段落全部保留；写入后记录新哈希与新尾部锚点。仍有写入者 running 时，报告写“最终性未验证”。

### 5. 最终验收

1. 用 `py -3` 运行 `skill-file-qa`，要求稳定指纹上的 `RESULT PASS`，并记录实际 PASS、FAIL、WARN、`Files (N)`、description 单行长度、正文行数、本地与跨 Skill 引用。
2. **验收后重扫。** QA 后按 2a 重扫写入记录并采样；出现新的成功写入时，作废旧 PASS，等新写入者 ready 后重跑。
3. 运行被接管 Skill 自带的真实正例与负例，退出码必须符合脚本契约；范围外脚本不执行，报告写“未执行（范围外）”。
4. **验收片段。** 只断言不变量（如退出码、`BASE_OK`）或日期化观测；漂移计数不写入片段，也不得作为 PASS 条件。
5. 重读两个以上关键文件，核对修正是否落地、并发内容是否仍在。
6. 确认无 `__pycache__`、无临时夹具、无多余文档；清理本次创建的临时目录。
7. 记录三方哈希与最终文件清单。

### 5b. 夹具清理与失败报告

删除 Skill 目录之外的夹具时，按异常类型处理，不要用“已清理”掩盖失败。

1. **先记录。** 记录路径、异常类型（WinError 5 / WinError 32 / 其他）与退出码。
2. **WinError 5（只读文件，常见于 Git 对象）。** 清除只读位后重试；Python 用 onexc 回调：

```python
import os
import shutil
import stat
import sys


def onexc(func, path, exc):
    os.chmod(path, stat.S_IWRITE)
    func(path)


shutil.rmtree(sys.argv[1], onexc=onexc)
```

3. **WinError 32（目录被占用）。** 找出仍持有句柄的进程，等待其释放后重试；PowerShell 的 Remove-Item -Force 不能解决占用。
4. **判定。** 只有 `test -e` 为假才写“已清理”；否则写“待处理”，列入报告并在下次会话继续。
5. **不升级为删除授权。** 清理失败不等于可以跳过备份或删除 Skill 内文件。

## 诊断

| 症状 | 原因 | 动作 |
|---|---|---|
| 规划时目标不存在，写入前出现 | 另一会话并发创建 | 停止 create，读取现有内容，进入能力矩阵与用户决策 |
| 目标不存在但不同名 Skill 职责部分重合 | 近重复触发源 | 用能力矩阵锁定真实增量，按 2quater 新建并写委派边界 |
| 写入前复查目标已存在 | 并发创建 | 停止 create，回到能力矩阵或按 2/2ter 接管 |
| 缩窄后新建时只扫描全部会话 | 把重合包或临时文件写入者算作新目标写入者 | 只统计新目标路径；当前会话单列 |
| 新目标 QA PASS 但 references 无哈希 | 校验器指纹只覆盖 SKILL.md | 分别记录 SKILL.md 与 references 哈希 |
| 新建后重合包哈希变化 | 重合包被并发改写 | 重读、重划边界、重跑 QA；不得宣称完成 |
| 触发词与相邻 Skill 重叠 | 描述未划边界 | 收窄触发词，在“什么时候不用”写明委派 |
| 归档副本被当作交付物改写 | 未区分加载副本与归档副本 | 只改目标 root；归档副本单列并报告 |
| 发现职责重合但用户未选择 | 决策缺失 | 保持停写；不得自行接管、改名或并存 |
| 用户选择保持现状但代理仍写入 | 把“只读保留”当成接管 | 立即停止；只撤回本会话新建的文件，不改动创建者文件；报告 KEEP-READ-ONLY |
| 默认门禁实际上会写盘 | 未先做副作用快照 | 按 `verifier-effets-de-bord-verification-lecture-seule` 隔离或停止，不宣称只读 |
| 门禁 PASS 但写入者仍在写入 | 把瞬时版本当最终版本 | 记录 revision，等稳定后重跑；报告可能过期 |
| 文档观测值与实物不一致 | 目标被并发改写或文档漂移 | 本分支只标注漂移；需要修正时先取得接管授权 |
| 文档声称围栏块豁免本地引用 | 断言未实测或来自二手摘要 | 建 A/B 夹具；以失败原文与退出码为准，纠正所有出现位置 |
| Edit 报 file changed since your last read | 并发写入或读取后又被改写 | 重读当前文件，重新定位；保留并发新增内容 |
| Edit 返回 0 occurrences found | 并发写入使 `old_string` 失效，或文本本就不匹配 | 先查写入者记录与当前哈希，重读定位；有并发则等待并重取基线 |
| 只读核查会话后来开始写入 | 把“读者”当成非写入者 | 以成功 Write/Edit 为准；读者随时可能转为写者，编辑前重扫 |
| 全部写入者 ready 后又出现新写入 | `ready` 只表示回合结束，写入者集合是动态的 | 新写入者加入等待，重取基线；不把旧指纹当终态 |
| 把 `list_chat_sessions` 的 ready 当写入证据 | 状态不是写入记录 | 只统计 JSONL 成功 Write/Edit；running/opening 列为潜在写入者，编辑前重扫 |
| QA PASS 后文件又被写入 | 未在验收后重扫写入者 | 作废旧 PASS，等新写入者 ready 后重跑 |
| 验收片段数字随夹具变化 | 把运行计数写成固定契约 | 只写不变量或日期化观测；不因数字变化改流程 |
| 写入者扫描把失败 Edit 当成功 | 未与 tool_result 配对 | 按 `tool_use_id` 配对，只统计成功结果；当前会话单列 |
| 校验报告指纹变化 | 校验期间仍有写入 | 等待稳定后重跑；不得使用旧 PASS |
| 接管后原目标目录仍被创建 | 流程串线 | 停止，报告冲突；接管模式下目标目录必须保持不存在 |
| 脚本哈希变化但无授权 | 并发改写或误改 | 停止，读当前脚本，确认差异来源；不静默接受 |
| QA PASS 但文件清单含缓存或临时文件 | 校验不覆盖目录清洁度 | 删除缓存与夹具后重跑，核对 `Files (N)` |
| 只修了 SKILL.md，references 仍保留旧断言 | 未做全量搜索 | 按唯一短语搜索并同步修正 |
| 共享参考文件被旧全文覆盖 | 写入前未重读尾部，或直接用旧内容 Write | 以当前尾部重新定位并只追加；恢复被覆盖的并发块；写入后核对哈希与锚点 |
| 接管后用户要求只写文档，代理仍改脚本 | 把缩窄交付当成完整接管 | 保留脚本，标为范围外；只在获得具体路径授权后备份并删除 |
| `Files (N)` 因脚本在磁盘上而不等于文档文件数 | 把范围外脚本从清单中隐去 | 如实报告 N 含范围外文件，不修改目录来凑数 |
| 清理报 WinError 5 | Git 对象只读 | chmod 可写位或用 onexc 回调后重试 |
| 清理报 WinError 32 | 目录被进程占用 | 等待句柄释放后重试；不要宣称已清理 |
| 报告写“已清理”但目录仍存在 | 以命令退出码代替磁盘状态 | 用 `test -e` 判定，存在即写“待处理” |
| 删除脚本前未备份 | 把清理与删除混淆 | 先备份到 Skill 目录之外并核对 SHA-256，再按授权删除 |
