## Sorties reproduites localement

Environnement : `git version 2.52.0.windows.1` ; `core.autocrlf=true` en portée **système** (`C:/Program Files/Git/etc/gitconfig`), portée globale non définie. Aucune configuration n'a été modifiée.

### Checkout fidèle

```text
i/lf    w/crlf  attr/                 	SKILL.md
STATUS_EMPTY_RC=0
```

Séquence : dépôt `main`, commit avec fichiers LF, `rm` des fichiers suivis, `git checkout -- .`, environnement `GIT_CONFIG_COUNT=1 GIT_CONFIG_KEY_0=core.autocrlf GIT_CONFIG_VALUE_0=true`.

### Réécriture brute et cache stat

```text
status_before_diff:
 M f.txt
diff_stat_rc=0
quiet_rc=0
status_after_diff:
 M f.txt
:100644 100644 422c2b7ab3b3c668038da977e4e93a5fc623169c 0000000000000000000000000000000000000000 M	f.txt
f.txt: needs update
refresh_rc=1
status_after_refresh:
 M f.txt
index_oid=422c2b7ab3b3c668038da977e4e93a5fc623169c
add_rc=0
status_after_add:
END_RC=0
```

Séquence : dépôt `main`, `f.txt` LF commité avec `autocrlf=true`, puis `printf 'a\r\nb\r\n' > f.txt` sans passer par Git. Le contenu est identique après conversion, mais `status` et `diff-files` restent ` M` ; `git add` remet le statut à vide. C'est exactement le symptôme qui avait produit un faux `SOURCE_DIRTY` dans la fixture d'origine.

### Extracteurs et CR final

```text
raw_len=4 tr_len=4 raw_eq_demo=yes tr_eq_demo=yes
py lstrip repr b'demo\r' len 5
py strip  repr b'demo' len 4
```

`sed` MSYS retire le CR (les deux variantes rendent `demo`) : un A/B fondé sur `sed` ne prouve rien. `lstrip(b' ')` conserve `\r` ; `strip()` le supprime et créerait un faux négatif.

## Vérifié, non vérifié

**Vérifié localement le 2026-10-26 :**

- L'environnement `GIT_CONFIG_COUNT`/`KEY_0`/`VALUE_0` impose `core.autocrlf` dans les deux sens (`true` et `false`) sur cette machine.
- Un checkout réel produit `i/lf w/crlf` et un statut vide.
- Une réécriture brute du même contenu produit ` M` avec `git diff --quiet`=0, `refresh` rc=1, et `git add` nettoie.
- `sed` MSYS rend `demo` (longueur 4) ; `lstrip` binaire rend `b'demo\r'` (longueur 5) ; `strip()` rend `b'demo'` (longueur 4).
- Le bloc découpé à 19 lignes échoue sur `comm` tout en rendant rc=0 et en passant les assertions d'absence.
- Le harnais de préflight est reproductible deux fois.

**Observé dans la session source, non rejoué intégralement ici :**

- Fixture de 48 contrôles, dont la variante CRLF, `RESULT PASS=48 FAIL=0`.
- Contrôle négatif du bloc complet : `DIFF_SKILL`, `NEG_RC=2`.

**Non vérifié / limites :**

- Le garde `tr -d '\r'` n'est **pas** prouvé porteur sous `sed` MSYS : `sed` retire déjà le CR. Il n'est porteur que pour un extracteur qui préserve le CR (Python binaire, autre outil). Ce Skill documente cette distinction, pas une validation universelle.
- Le comportement du cache stat (statut ` M` alors que `diff --quiet`=0) est observé sur Git 2.52.0.windows.1. Une autre version peut le corriger ; le harnais le signale comme dérive d'environnement, pas comme défaut du garde.
- Aucune PR réelle, aucun dépôt de production, aucun réseau n'a été utilisé.
- La tentative `fee499a1` s'est arrêtée avant toute écriture ; elle n'a produit ni ce `SKILL.md` ni ses ressources.
