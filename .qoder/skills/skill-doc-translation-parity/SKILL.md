# Skill 文档译本与结构对等

> 为 Skill 的 `SKILL.md` 与 `references` 文档生成完整译本，并用脚本守住结构对等。源语言文件始终是权威版本；译本只放在 `references/` 下，不改变原文件的事实与数字。

## 何时使用

- 用户要求把某个 Skill 的 `SKILL.md` 或 `references` 文档翻译成中文（或其他目标语言），并保留源语言原版为权威版本。
- 已有 `-zh.md` 译本，需要检查它是否漏段、漏数字、漏哈希，或代码块、表格、反引号标识符与原文不一致。
- 源文件刚更新，需要同步译本并证明没有漂移。
- 需要为译本写权威声明、在源 `SKILL.md` 资源列表登记，并在交付前跑 `skill-file-qa`。

## 不适用与边界

- 单个 `SKILL.md` 内并列两种语言的交付，用 `bilingual-skill-parity`；本 Skill 处理独立文件译本。
- 普通文章、营销文案或没有源文件的改写，不需要也不应套用结构对等。
- 脚本只检查结构与你选定的受保护事实，不判断译文语义质量，也不替代人工通读。
- 不翻译代码块、命令、路径、标识符、错误消息、URL、数字与哈希。

## 不可协商规则

1. **源文件权威。** 不原地翻译，不为了通过检查删改源文件的数字、段落或事实。发现源文件错误时单独说明并取得确认。
2. **一源一译。** `SKILL.md` 译为 `references/skill-<lang>.md`；`references/<name>.md` 译为 `references/<name>-<lang>.md`。中文用 `zh`。
3. **完整翻译。** 逐节翻译，不摘要、不合并、不拆分章节；章节顺序与层级保持不变。
4. **受保护内容逐字保留。** 围栏代码块（含语言标记）、命令、路径、标识符、错误消息、URL、数字、SHA-256 与反引号内容保持原文；译文只改叙述文字。
5. **权威声明。** 译本顶部加一段声明，用相对链接指回源文件，并写明源语言版为准。
6. **登记。** 在源 `SKILL.md` 的资源列表新增一行，列出译本并注明源语言版为准。
7. **不复制成第二个 Skill。** 译本若保留 frontmatter，`name` 必须与源完全一致；不得把译本注册成可安装 Skill。
8. **同步维护。** 源文件变更后，在同一次改动中更新译本并重跑对等检查；过期译本按缺陷处理。

## 文件与命令

| 用途 | 路径 |
|---|---|
| 对等检查器 | `scripts/check_translation_parity.py` |
| 详细契约 | `references/translation-contract.md` |

```bash
py -3 scripts/check_translation_parity.py <source.md> <translation.md>
py -3 "<skills-root>/skill-file-qa/scripts/validate_skill.py" "<skill-dir>" \
  --workspace "<workspace-root>" --stable-seconds 2 --stability-timeout 30
```

- Windows 上若 `python` 指向 Microsoft Store 别名，改用 `py -3`。
- 对等检查器只读，退出码 `0` 通过、`1` 对等失败、`2` 用法或环境错误。
- 先修译本，再重跑；不要通过删改源文件让检查通过。

## 流程

### 1. 读取实物

读取源文件、现有译本与目录清单；记录每个文件的 SHA-256。不要凭记忆翻译，也不要凭摘要补段。

### 2. 建立结构地图

逐节记录标题层级、表格行列、代码块数量与语言、清单项数，以及全部反引号标识符、数字与 SHA-256。源文件是唯一基准。

### 3. 逐节翻译

按源文件顺序翻译叙述文字；受保护内容原样带入。宁可句子生硬，也不要意译掉限定词、数量或工具名。

### 4. 声明与登记

在译本顶部加入权威声明，并在源 `SKILL.md` 的资源列表登记译本。

### 5. 对等检查

对每一对源文件与译本运行检查器。失败时只改译本；逐项定位缺失或多余的数字、反引号标识符、表格行与标题。

### 6. 结构与格式验收

运行 `skill-file-qa` 的验证器，要求 `RESULT PASS`、0 FAIL。再重读实际文件，核对 frontmatter、单行 description、正文行数、资源列表与相对链接。

### 7. 报告

列出每对文件的检查结果、实际 SHA-256、未覆盖项（例如纯文本项目符号、语义质量）与是否改动源文件。

## 对等维度

| 维度 | 检查方式 | 失败含义 |
|---|---|---|
| 代码块 | 数量、围栏语言、内容逐字一致（支持反引号与波浪线围栏；忽略行尾空白与换行风格） | 命令、路径或报告模板被翻译 |
| 表格 | 每张表的行数（含表头）与列数、每行宽度（表头可含或不含前导竖线） | 漏行、并格或删列 |
| 标题 | 层级序列完全一致，并报告 H1/H2/H3 计数 | 章节遗漏、合并或升降级 |
| 清单 | `- [ ]` 与 `- [x]` 项数分别一致 | 完成检查项被删或状态被改 |
| 反引号标识符 | 多重集完全一致 | 标识符被翻译、漏写或多加反引号 |
| 数字 | 排除代码块与行内代码后，归一化千位分隔符与小数逗号 | 数量、阈值或日期漂移 |
| SHA-256 | 64 位十六进制多重集一致（小写归一；行内代码中的哈希由反引号标识符比较） | 哈希被截断、改写或遗漏 |

## 已验证的失败与修正

| 症状 | 原因 | 动作 |
|---|---|---|
| 源文两处 `9` 在译本缺失，旧检查器报 `9.0` | 旧检查器把数字按浮点归一化 | 在译本补回两处数字，源文不动 |
| 译本时间戳多一对反引号 | 受保护片段被额外标记 | 去掉译本多余反引号，与源文一致 |
| 旧检查器只打印反引号差异却不失败 | 差异未计入失败集合 | 新检查器把标识符差异计为 FAIL |
| 表格或标题把代码块内容算进去 | 扫描前未屏蔽围栏 | 先标记围栏行，再统计表格与标题 |
| 控制台因中文输出崩溃 | Windows 控制台编码非 UTF-8 | 输出保持 ASCII，非 ASCII 用 `backslashreplace` |
| 未闭合围栏导致匹配吞掉全文 | 正则跨块匹配 | 围栏状态机扫描，未闭合返回 2 |
| 波浪线（`~~~`）或四反引号围栏被忽略或误判未闭合 | 围栏正则只认三反引号 | 按字符与长度匹配开闭围栏；未闭合仍返回 2 |
| 无前导竖线的表格漏检 | 表头识别要求以竖线开头 | 表头含竖线即可识别，并收集连续含竖线的行 |
| 清单 `[x]` 改成 `[ ]` 但总数不变仍通过 | 只比较清单总数 | 分别比较 `- [ ]` 与 `- [x]` 的数量 |

## 完成定义

- [ ] 源文件与译本均已实际读取，并记录 SHA-256。
- [ ] 译本命名、权威声明与回链符合规则。
- [ ] 源 `SKILL.md` 资源列表已登记译本，并注明源语言版为准。
- [ ] 每一对源/译文件的对等检查退出 `0`，输出 `RESULT PASS`。
- [ ] 代码块、表格、标题、清单、反引号标识符、数字与 SHA-256 全部通过。
- [ ] `skill-file-qa` 通过，0 FAIL。
- [ ] 未为了迁就对等而改写源文件；改动仅限译本与资源登记。
- [ ] 报告中区分已检查项、未覆盖项与语义质量（脚本不判断）。

## 资源

- `scripts/check_translation_parity.py`：只读结构对等检查器；ASCII 输出，退出码 0/1/2。
- `references/translation-contract.md`：命名、声明模板、受保护内容、归一化规则、CLI 契约、案例与局限。
- `bilingual-skill-parity`：单文件双语 `SKILL.md` 的对等流程。
- `skill-file-qa`：写入后的结构、引用与稳定性验收。
