# 译文契约与对等规则

> 本文配套 [SKILL.md](../SKILL.md)，规定 Skill 文档独立译本的命名、声明、受保护内容、检查器契约与已知局限。源语言文件始终为权威版本。

## 1. 适用范围

- 适用于 Skill 的 `SKILL.md` 与 `references` 下的 Markdown 文档。
- 单个 `SKILL.md` 内并列两种语言的交付，使用 `bilingual-skill-parity`，不使用本契约。
- 普通文章翻译不需要结构对等检查；不要为了套用本流程而拆分原文。

## 2. 命名与放置

| 源文件 | 中文译本 |
|---|---|
| `SKILL.md` | `references/skill-<lang>.md` |
| `references/<name>.md` | `references/<name>-<lang>.md` |
| 其他目标语言 | 用 ISO 639-1 小写码替换 `<lang>` |

- 中文固定用 `zh`；同一种语言只保留一份译本。
- 译本不放到新的 Skill 目录，也不在 `SKILL.md` 之外另建索引文件。
- 源文件重命名时同步重命名译本，并更新资源登记。

## 3. 权威声明模板

```text
> 本文是 [<source-file>](<relative-link>) 的完整中文译本，源语言原版为权威版本。
> 命令、路径、标识符、数字、哈希与代码块保持原文。
```

- 相对链接从译本所在目录计算：`SKILL.md` 的译本在 `references/` 下，回链写 `../SKILL.md`；同级参考文档直接写文件名。
- 声明本身不得引入新的数字、哈希或反引号标识符，否则会增加对等检查噪声。
- 声明的语言与译本一致；不要只写一句“见原文”而不给链接。

## 4. 翻译与保留

| 处理 | 内容 |
|---|---|
| 翻译 | 标题文字、段落、表格表头与说明文字、列表叙述、图片替代文本、强调语气 |
| 原样保留 | 围栏代码块及围栏语言、行内代码、命令、路径、标识符、错误消息、URL、数字、SHA-256、表格行列数、标题层级与顺序、清单项数、frontmatter 的 `name` |

- 代码注释也保留原文；需要解释时在代码块外写译文。代码块内出现自然语言注释时，优先保持原样，避免对等失败。
- 不新增总结段，不删除限定词（例如 only、must、never、不得、仅）。
- 表格可以调整分隔线宽度与对齐方式，但不得增删行、列或合并单元格。
- 标题可以翻译文字，但不得改变级别、顺序或数量。
- 数字、日期、哈希与版本号逐字复制；不要本地化小数点、千位分隔符或日期格式。

## 5. 检查器契约

在 Skill 目录中运行：

```bash
py -3 scripts/check_translation_parity.py <source.md> <translation.md>
```

退出码：

| 码 | 含义 |
|---|---|
| 0 | 全部对等检查通过，输出 `RESULT PASS` |
| 1 | 至少一项对等失败，输出 `RESULT FAIL` |
| 2 | 参数、文件缺失、编码或围栏未闭合等环境错误 |

固定检查顺序：frontmatter 名称、代码块、表格、标题、清单、反引号标识符、数字、SHA-256。每项输出 `PASS` 或 `FAIL`，最后输出 `Summary` 与 `RESULT`。

### 5.1 归一化规则

| 维度 | 规则 |
|---|---|
| frontmatter | 两侧都跳过；若都声明 `name`，必须完全相同；译本不得声明源文件没有的 `name` |
| 代码块 | 状态机扫描反引号与波浪线围栏；开围栏至少 3 个，闭围栏同字符且不短于开围栏；未闭合返回 2；语言标记小写比较；内容统一换行、去行尾空白、去首尾空行后逐字比较 |
| 表格 | 以“表头 + 分隔行”识别；表头可含或不含前导竖线，数据行是连续非空且含竖线的行；行数含表头、不含分隔行；比较每张表的行数与列数，并检查每行宽度 |
| 标题 | 比较 H1–H6 的层级序列；标题文字可翻译；报告各层计数 |
| 清单 | 分别统计任意缩进的 `- [ ]` 与 `- [x]` 项数；两类数量都必须一致 |
| 反引号标识符 | 排除围栏后提取行内反引号内容，去首尾空白，按多重集完全一致比较 |
| 数字 | 排除围栏与行内代码，去掉有序列表标记；去空格、窄空格、不换行空格与撇号；`1,234` 视为 `1234`；无小数点时的逗号视为小数逗号；按字面比较，`9` 与 `9.0` 不相等 |
| SHA-256 | 排除围栏与行内代码后提取 64 位十六进制，转小写后按多重集比较；行内代码中的哈希由反引号标识符检查 |

- 围栏按字符与长度成对匹配：反引号只关闭反引号，波浪线只关闭波浪线；关闭围栏不得短于开启围栏。
- 行内代码中的数字和哈希由“反引号标识符”检查，不在“数字”与“SHA-256”中重复计入。
- 差异最多列出 10 项，可用 `--max-report` 调整。
- 输出保持 ASCII；路径或内容中的非 ASCII 字符以 `backslashreplace` 形式显示，避免 Windows 控制台编码崩溃。

## 6. 失败处理顺序

1. 先修结构：代码块、表格、标题、清单的差异通常意味着漏段、并段或误译了围栏。
2. 再修事实：反引号标识符、数字与哈希缺失或多出，逐项从源文件复制，不凭印象改写。
3. 不通过删改源文件让检查通过。若怀疑源文件本身有误，停止并单独说明，取得确认后再改源文件与译本。
4. 每修一处重跑检查器；全部通过后再运行 `skill-file-qa`。

`skill-file-qa` 验证 frontmatter、单行 description、正文行数、本地引用、跨 Skill 引用、代码块语法、并发写入与起止指纹。它不检查译文结构对等，因此两项都要做。

## 7. 已验证案例

来自一次 Cs-133 Skill 的真实翻译，均只改译本：

- 源文正文两处数字 `9` 在译本缺失；旧检查器把数字归一化为 `9.0` 后报告差异。修复方式是在译本补回两处数字，源文未动。
- 译本把时间戳额外包进反引号，导致行内标识符多重集多出一项。修复方式是去掉译本的反引号，与源文保持一致。
- 旧的一次性脚本只打印反引号差异、不把差异计入失败集合；本 Skill 的检查器把标识符差异计为 `FAIL`。
- 旧脚本用跨块正则提取代码块，未闭合围栏会吞掉后文；本检查器使用围栏状态机，未闭合时以退出码 2 结束。
- 旧脚本统计表格与标题时未排除代码块内容；本检查器先标记围栏行再统计。
- 旧脚本在 Windows 控制台输出中文时触发 `UnicodeEncodeError`；本检查器输出 ASCII。

## 8. 维护与局限

- 源文件变更后，在同一次改动中更新所有语言译本；只更新源文件会让译本立即过期。
- 新增或删除译本时，同步更新源 `SKILL.md` 的资源列表；登记行注明源语言版为准。
- 检查器不判断语义质量、术语一致性或语气；仍需人工通读。
- 检查器不比较纯文本项目符号数量、链接目标是否等价、图片内容；这些由人工审查与 `skill-file-qa` 的引用检查覆盖。
- 若源文与译本同时存在同一个错误数字，结构检查会通过；这属于源文审查问题，不能由本流程证明数值正确。
- 检查器只读，不写任何文件；修复由使用者对译本执行。
