# Skill 工具契约审计

## 目标与边界

在承诺「用 X 工具校验 Y」之前，用文件系统与实测 `--help` 证明 X 能做 Y；能启动且参数匹配还不够，再用一次真实变异证明 X 能发现 Y 中的漂移。证明不了就显式回退并标注，而不是按记忆或描述调用。

- 本 Skill 只做只读契约审计、一次负向能力探针与结构回退，不修改被审计的 Skill。
- 负向测试只在副本上进行；原文件必须保持不变。
- 写入后的格式验收用 `skill-file-qa`；来源会话证据核实用 `audit-session-evidence`。
- 单文件双语与独立译本的结构对等，权威工具分别是 `bilingual-skill-parity` 与 `skill-doc-translation-parity`；本 Skill 的 `compare` 仅在它们不可用时作回退。
- 系统性反例回归用 `skill-validator-selftest`；本 Skill 只做一次能力探针。

## 何时使用

- 方案或 `SKILL.md` 即将写明「用某工具校验」，但尚未实际运行它。
- 某 Skill 声明的 `scripts/` 路径不存在，或 `scripts/` 目录为空、疑似并发创建中。
- 需要两个文件输入，而工具只接受目录或单个文件（或相反）。
- `skill-file-qa` 通过，但反引号中的 Skill 名只证明了 `SKILL.md` 存在。
- 退出码看起来成功，但命令经过了管道；或中文输出在 Windows 控制台崩溃。

## 不可协商规则

1. **以实物为准。** 只相信磁盘文件与当前环境的 `--help`，不相信 Skill 描述、上一次会话的结论或摘要。
2. **只读。** 不修改他人 Skill 来让契约「对上」；回退脚本只放 `.qoder/tmp/<session>/`。
3. **不静默替换。** 工具不可用时，换用具名替代或回退，并在报告里写明原因。
4. **不虚报。** 没有实际运行原工具，就不得写「已用 X 验证通过」；回退结果必须标注「不是原声明工具」。
5. **退出码不经管道。** `cmd | head; echo $?` 得到的是 `head` 的状态；直接运行后再取退出码。
6. **编码固定。** Windows 使用 `py -3` 与 `PYTHONIOENCODING=utf-8`；审计器输出保持 ASCII。
7. **留痕。** 记录被审计 `SKILL.md` 与脚本的大小、SHA-256、命令与退出码。
8. **负向测试才算能力证明。** 正例 PASS 只证明当前输入通过；在报告某校验器「可用」前，至少做一个真实变异，先用哈希或精确计数断言副本已改变，再确认失败分支返回预期非零退出码。变异后仍 PASS 时，如实标注该工具不覆盖此类漂移。

## 审计流程

### 1. 定位声明资源

读取目标 `SKILL.md`，收集反引号或 Markdown 链接中以 `scripts/`、`references/` 开头的路径。先确认它声明了什么，而不是它声称能做什么。

### 2. 检查存在性

逐个查磁盘；声明必须是具名文件，具名路径若解析为目录会判 FAIL，裸目录（如 `scripts/`）不进入清单。声明缺失时停止依赖该工具，不要继续按文档调用。

### 3. 探测入口与参数元数

对存在的 Python 脚本运行 `--help`，记录 `usage:`、必需/可选位置参数与退出码。无 `usage`、含子命令表 `{a,b}` 或含可变参数（`paths [paths ...]`）时标记 UNVERIFIED，不断言元数。

### 4. 断言输入形态

把预期形态与 `usage` 对比：需要两个文件就必须有两个必需位置参数；需要目录或单文件就必须恰好一个位置参数。不符即判定契约不匹配。

### 5. 判定与回退

按下方决策表处理。回退只用于本次验证，不作为该工具的验收记录。契约匹配但尚未做负向测试时，只能标为「契约匹配」，不能标为「已验证可用」。

### 6. 检测能力负向测试

契约匹配后、报告「可用」前执行：

1. 只在副本上变异：复制到 `.qoder/tmp/<session>/negative/`，绝不改原文件。
2. 选结构性、可精确定位的变异点：围栏语言、代码块文本、反引号标识符、数字、表格列数、标题层级。不要只改散文，因为结构检查器不覆盖散文语义。
3. 先证明变异生效：记录变异前后 SHA-256，或断言精确出现次数。未改变就停止，不得把校验器的 PASS 当作结论——这是假 PASS 的常见来源。
4. 直接运行校验器并读取退出码，不经管道。期望失败分支返回 `1`（或该工具文档声明的失败码），且输出包含可辨识的失败项。
5. 变异后仍 PASS：判定该工具不覆盖此类漂移；换工具、回退或标注覆盖边界，不得声称「已验证能发现」。
6. 清理副本；需要复查时保留 `.qoder/tmp/<session>/negative/` 并在报告中写明路径。
7. 报告写清：变异点、变异前后哈希、命令、实际退出码、失败输出摘要与未覆盖项。

### 7. 报告

逐项标为「已验证 / 回退验证 / 未验证 / 阻塞」，附命令、退出码与哈希。模板见 `references/contract-audit.md`。

## 命令

```bash
py -3 scripts/audit_contracts.py audit "<skill-dir>" --help-probe \
  --expect "scripts/<tool>.py=two-files"

py -3 scripts/audit_contracts.py compare "<source.md>" "<translation.md>"

py -3 scripts/audit_contracts.py mutate \
  --copy "<translation.md>" --replace "<old>" --with "<new>" --occurrence 1 \
  --workdir ".qoder/tmp/<session>/negative" --keep \
  -- py -3 "<validator.py>" "<source.md>" "{mutated}"

py -3 scripts/audit_contracts.py mutate "<source.md>" --out "<copy.md>" \
  --kind inline --validator 'py -3 <validator.py> "<source.md>" {target}'
```

- `audit`：声明资源存在性、SHA-256、`--help` 元数、`--expect` 断言。`--expect` 必须与 `--help-probe` 同用，否则退出码 `2`。它不自动跟进被引用 Skill；需要时对每个被引用 Skill 单独 `audit`（可直接传已安装 Skill 名）。
- `compare`：标题、表格、代码块、清单、内联标识符、数字 6 项结构对比。
- `mutate` 替换模式：复制 `--copy` 到临时目录，精确替换一处，断言副本哈希改变，再运行校验器；`{mutated}` 替换为副本路径，未提供时自动追加。
- `mutate` 确定性模式：`--kind` 内置 `heading`/`table`/`code`/`language`/`checklist`/`inline`/`number` 七种结构变异，断言对应维度确实改变，再按 `--validator` 运行；`{target}` 替换为副本路径，`--expect-exit` 默认 `1`。
- 退出码：`audit`/`compare` 为 `0` 通过、`1` 缺口或对等失败、`2` 用法或环境错误、`3` 仅有未验证项（`RESULT UNVERIFIED`）；`mutate` 为 `0` 变异生效且校验器返回预期非零、`1` 变异生效但校验器返回其他码或变异未生效/源文件被改、`2` 用法/环境/目标未命中/超时。
- `mutate` 两种模式都不写原文件，并在变异前后核对原文件哈希。替换模式复制到 `--workdir`（默认 `.qoder/tmp/negative`，相对当前目录），默认清理副本，`--keep` 保留并打印路径；确定性模式写入 `--out`，不自动清理，校验器以 `--out` 所在目录为工作目录。
- `--help` 会执行脚本顶层代码；只对本地可信 Skill 探测，不自动执行无参数分支。

## 契约核对表

| 维度 | 通过条件 |
|---|---|
| 存在性 | 每个具名声明都解析为文件；具名路径是目录会判 FAIL；裸目录不进入清单 |
| 入口 | 文档命令能在当前环境启动，解释器与工作目录明确 |
| 参数元数 | `usage` 的必需/可选位置参数与预期一致 |
| 输入形态 | 目录、单文件、双文件与该工具实际接受的一致 |
| 退出码 | 直接运行读取，失败分支有可辨识输出 |
| 输出编码 | 非 ASCII 不导致崩溃；探测固定 UTF-8 |
| 只读性 | 审计动作不写入被审计目录 |
| 文档一致性 | SKILL.md 的命令、参数与退出码与实际 `--help` 一致 |
| 检测能力 | 至少一个真实变异生效，校验器返回预期非零退出码并指出失败项；未覆盖项已注明 |

### 输入形态断言

| 断言 | 含义 | 例 |
|---|---|---|
| `dir` / `file` | 位置参数总数为 1，并要求 `--help` 描述为目录 / 文件 | `[skill_dir]`、单文件双语校验 |
| `optional-dir` / `required-dir` / `one-file` | 精确断言 0 必选 + 1 可选 / 1 必选 + 0 可选 | 需要区分可选性时 |
| `two-files` | 恰好两个必需位置参数，且都描述为文件 | `source translation` |
| `required=N,optional=M` / `total=N` | 只断言元数，不断言类型 | 帮助文本无法判定类型时 |

`dir` 与 `file` 是 `total=1` 别名，不区分必需/可选，但会校验 `--help` 的目录/文件描述。可变参数（`paths [paths ...]`）与子命令表（`{audit,compare}`）无法推导元数，结果为 UNVERIFIED（退出码 `3`），不能当作通过。

## 决策表

| 情形 | 动作 |
|---|---|
| 声明脚本缺失 | 不依赖；找替代或回退；报告缺失路径与声明出处 |
| `scripts/` 为空、Skill 刚出现 | 视为并发创建中；本次不依赖；不修改对方；报告「未验证」 |
| 参数元数不符 | 不按预期调用；换工具或回退；报告实际 `usage` |
| 输入形态不符 | 换匹配工具（如单文件双语 → 独立译本）；否则回退 |
| `--help` 无 `usage` 或超时 | 标记未验证；不得断言元数；记录原始错误 |
| 仅 Skill 名能解析 | 用 `audit` 直接审计被引用 Skill 的声明资源与脚本 |
| 文档与实物矛盾 | 以实物为准；报告漂移，不修改对方 |
| 负向测试仍 PASS | 该工具不检查这类漂移；换工具、回退或标注覆盖边界；不得记为「已验证能发现」 |
| 变异未生效 | 哈希或精确计数未变；停止，修正变异点；不得把校验器的 PASS 当作结论 |

## 只读回退

满足任一条件才回退：声明工具缺失、并发创建中、参数不符、形态不符，且已有命令与退出码为证。

1. 不把脚本写入对方目录；临时文件放 `.qoder/tmp/<session>/`。
2. 用 `compare` 做 6 项结构对比；先屏蔽围栏代码块，再统计标题、表格与清单。
3. 报告中写「回退验证，不是原声明工具的检查」。
4. 列出未覆盖项：语义质量（含在译本末尾追加纯文本段落）、纯文本项目符号、未加反引号的声明、HTML 结构、链接可达性。
5. 不得把回退结果记作原工具的通过记录。

## 完成定义

- [ ] 被审计的 `SKILL.md` 与脚本均已实际读取，并记录 SHA-256。
- [ ] 每个声明资源都有存在性结论；缺失项已列出。
- [ ] 每个被依赖脚本都有 `--help` 的 `usage`、元数与退出码，或明确标为未验证。
- [ ] 输入形态断言与实际 `usage` 对照过，结论为 PASS、FAIL 或 UNVERIFIED。
- [ ] 回退（如有）已标注，并列出未覆盖项。
- [ ] 至少一个负向变异已断言生效（哈希或精确计数改变），并确认校验器返回预期非零退出码；未做则标为未验证。
- [ ] 负向测试的覆盖边界（尤其散文语义）已写入报告。
- [ ] 报告区分「已验证 / 回退验证 / 未验证 / 阻塞」，未虚报原工具通过。
- [ ] 未修改被审计 Skill；临时产物位置已说明。

## 资源

- `scripts/audit_contracts.py`：只读审计器；`audit`、`compare`、`mutate` 三个子命令，ASCII 输出，退出码 0/1/2/3（mutate 见命令节）。
- `references/contract-audit.md`：契约维度、负向测试协议、决策表、2026-10-26 真实案例、回退协议、报告模板与局限。
- `skill-file-qa`：写入后的格式与引用验收。
- `audit-session-evidence`：创建或更新 Skill 前的来源会话证据核实。
- `skill-update-concurrency-safe`：目标目录并发写入时的稳定性检查。
- `skill-validator-selftest`：校验器本身的系统性反例回归；本 Skill 只做一次能力探针。
