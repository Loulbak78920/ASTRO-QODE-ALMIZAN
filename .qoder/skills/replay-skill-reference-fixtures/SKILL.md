# 参考夹具重放

## 目标

参考文件里的「实测输出」只有能被自带夹具复跑时才算证据。修改或引用这类参考文件之前，先原样重放，再决定改夹具、改记录还是标为未覆盖；不用推测替代实测，也不为让记录成立而伪造输出。

## 触发条件

- 参考文件含「实测输出」「来源实测」「复跑夹具」「验证记录」等段落；
- 准备修改带这类参考文件的 Skill，或要引用其中输出作为结论；
- 记录中的条数、退出码与紧邻的夹具步骤看起来矛盾；
- 夹具在用例之间复位、移动或重建文件；
- 交接或发布前，需要证明文档中的命令可以逐字复跑。

## 不可协商规则

1. 以实物为准：只相信磁盘上的文件与当前环境的真实输出。
2. 重放阶段只读且原样：不改命令、不改断言字段、不跳过用例、不先修夹具。
3. 冲突不伪造：记录与夹具不一致时，先分类，再只改有证据的一方；不得为匹配夹具而改写记录中的输出。
4. 只断言稳定字段：`RESULT`、退出码、异常类型、标签、计数；不比对 blob 前缀、commit ID、mtime、临时路径。
5. 退出码先取后滤：先运行并立即保存 `$?`，再做过滤；管道会吞掉真实退出码。
6. 隔离：夹具只建在 `.qoder/tmp/replay-fixtures-<UTC 时间戳>/`，结束后只删除该目录。
7. 双采样：读取或写入目标 Skill 前后，至少间隔 2 秒比较 size、mtime、SHA-256；变化时停止并重读。
8. 修正只用最小编辑，只改被证据指出的那一处；保留原始记录，或注明删除理由与日期。
9. 未执行、未触发、环境不允许的分支单列为未覆盖，不写成已验证。
10. 不修改夹具依赖的脚本或数据源；不提交、不推送。

## 第 1 步 — 定位记录与夹具

```bash
TARGET="$HOME/.qoder/skills/<skill-name>"
grep -rn -E "实测|复跑|fixture|EXIT=|RESULT |退出码" "$TARGET" --include="*.md"
```

为每条记录配对：前置状态、命令、期望 `RESULT`、期望退出码、期望异常类型。再检查夹具是否自洽：用例之间是否复位、删除或重建文件；记录里的条数是否能由这些步骤产生。没有夹具、命令依赖交互或私有环境时停止，报告「不可重放」，不凭空重建。

## 第 2 步 — 双采样与基线

```bash
find "$TARGET" -type f -exec sha256sum {} + | sort
find "$TARGET" -type f -printf '%P %s %T@\n' | sort
sleep 2
find "$TARGET" -type f -exec sha256sum {} + | sort
```

两次一致才继续。同时记录夹具调用的外部脚本的 SHA-256、size、mtime；目标 Skill 被并发改写时停止，参考 `skill-update-concurrency-safe`。

## 第 3 步 — 隔离重放

按参考文件原样构建夹具，不要「顺手修正」。为每个用例分别保存输出与退出码：

```bash
TMP=".qoder/tmp/replay-fixtures-$(date -u +%Y%m%dT%H%M%SZ)"
mkdir -p "$TMP" || { echo "FAIL temp"; exit 1; }

case_run() {
  name="$1"; shift
  "$@" >"$TMP/$name.out" 2>&1
  printf '%s' "$?" >"$TMP/$name.code"
  printf '=== %s EXIT=%s ===\n' "$name" "$(cat "$TMP/$name.code")"
  tail -n 40 "$TMP/$name.out"
}

FAILS=0
assert_case() {
  name="$1"; want="$2"; pattern="$3"
  got=$(cat "$TMP/$name.code")
  if [ "$got" = "$want" ] && grep -q -- "$pattern" "$TMP/$name.out"; then
    printf 'OK %s exit=%s contains %s\n' "$name" "$got" "$pattern"
  else
    printf 'MISMATCH %s want_exit=%s got_exit=%s pattern=%s\n' "$name" "$want" "$got" "$pattern"
    FAILS=$((FAILS + 1))
  fi
}
```

用法：

```bash
case_run fresh py -3 "$DEP" --skill "$SRC" --repo "$REPO"
assert_case fresh 0 '^RESULT FRESH$'
```

- 退出码写入独立的 code 文件，避免函数返回值或管道覆盖。
- 不要在 `case_run` 调用后接管道；过滤放到断言里。
- 用例之间确实相互依赖时按夹具原样累计执行；需要独立重启时整段重建，不手工回滚。
- 每个用例至少断言：`RESULT` 行、退出码、关键异常类型；数值字段只在稳定时断言。

## 第 4 步 — 比对与分类

| 现象 | 分类 | 动作 |
|---|---|---|
| 输出、退出码、异常类型全符合 | 已复现 | 记录实测值，进入第 6 步 |
| 夹具步骤与记录矛盾（复位、漏步骤、路径不同） | 夹具漂移 | 修夹具，保留原记录，注明日期与理由 |
| 记录取自旧版本或不同环境 | 记录错误 | 用本次实测替换记录，附命令、日期、环境 |
| 只有 blob、commit、mtime、临时路径不同 | 非确定性 | 断言稳定字段，说明哪些字段不比对 |
| 记录块省略计数行但断言字段一致 | 展示差异 | 不改记录；按字段判定 |
| 命令不可执行、依赖缺失、需交互 | 阻塞 | 停止；不重建夹具、不改记录 |

## 第 5 步 — 修正与保留证据

1. 夹具漂移：删除或修正造成矛盾的那一步，加一行注释说明原步骤为何不能复现记录。
2. 记录错误：只替换实测有据的部分；保留命令、日期、环境与必要的旧值。
3. 非确定性：不要写入新的具体 blob 或 commit；说明断言范围。
4. 环境差异：标为覆盖边界，不修改记录来迁就本机。
5. 每次只改一处，修改后重新读取文件；不要重写整份参考。

## 第 6 步 — 干净复跑、验收与报告

1. 删除第 3 步的临时目录，用同一夹具从零重建，完整重放全部用例，不跳过、不复用中间状态。
2. 记录每个用例的实测输出、退出码与断言结果。
3. 对目标 Skill 运行 `skill-file-qa`；失败时修复或如实报告，不宣称通过。
4. 只删除本次唯一临时目录，并确认它不存在；不要清理其他会话的目录。
5. 双采样目标文件 SHA-256，报告旧值、新值与修改点。

```text
目标        : <skill 路径>
参考文件    : <路径> | SHA-256 <前> -> <后>
用例        : <n>/<N> 符合 | 失败 <#>
分类        : 夹具漂移 <n> | 记录错误 <n> | 非确定性 <n> | 阻塞 <n>
修正        : <文件与段落> | 保留证据 <是/否>
复跑        : <n>/<N> 符合 | 退出码 <...>
静态验收    : skill-file-qa <PASS/FAIL>
临时目录    : <路径> 已清理 | 残留 <...>
指纹        : <文件> <旧> -> <新> | 双采样 <一致/不一致>
```

## 错误与陷阱

| 症状 | 原因 | 动作 |
|---|---|---|
| 记录写「2 条异常」，复跑只有 1 条 | 夹具在用例间复位了被改文件 | 修夹具，保留记录并注明理由 |
| 所有用例退出码都是 0，包括用法错误 | 退出码在管道或 `cat` 之后读取 | 先运行、保存退出码、再过滤 |
| blob 或 commit 每次不同 | 内容寻址与提交哈希随夹具变化 | 只断言 `RESULT`、退出码、异常类型 |
| 用例相互污染 | 夹具累计修改同一目录 | 按原样执行；独立复跑时整段重建 |
| 首次复跑就改夹具 | 把「复跑失败」当「夹具写错」 | 先完成分类，再改有证据的一方 |
| 删除范围过宽 | 清理命令指向 `.qoder/tmp` 或工作区 | 只删本次唯一目录，先打印路径 |
| `NOTE not a repository` 后得到 `NONE` | 路径存在但非 Git 仓库 | 原样报告，不改成 FRESH |
| Windows 下 `/` 路径被改写 | Git Bash 的 MSYS 路径转换 | 记录观测；未下结论的标为未覆盖 |
| 重放中目标 Skill 变化 | 另一会话并发写入 | 停止；重读；在新版本上从头重放 |
| 静态 QA 通过就宣称已复现 | QA 不执行夹具 | 重放结果单独报告 |
