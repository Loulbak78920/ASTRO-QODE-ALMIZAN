# 迁移会自述位置的 Skill

## 目标

Skill 常在自己的 SKILL.md 与证据文件里写明「装在哪、对谁可见、是否已移动」。移动或复制目录后，路径前缀可以批量替换，但这些不含路径的叙述不会被 grep 命中。本 Skill 在迁移后审计这类叙述，覆盖旧/新前缀 0/0、无需替换但叙述已过期的情况，并在新路径完成验证。

## 何时使用

- 移动或复制一个会描述自身安装位置、可用范围或迁移状态的 Skill。
- 迁移后前缀计数为 0/0，准备直接判定「无需更新」。
- 证据文件或正文仍写「未移动」「仍在用户级」「仅当前项目可见」「其他项目需另行安装」。
- 移动后需要证明旧目录消失、哈希不变，并在新路径复跑检查。
- 用户询问移动后 Skill 是否出现在项目级列表、是否需要重载。

不适用于：路径前缀替换与移动的完整步骤（`skill-absolute-path-references`）；写入前的并发保护与备份（`skill-update-concurrency-safe`）；结构校验细节（`skill-file-qa`）；对外发布归档（`publier-skill-qoder-vers-depot-git`）。

## 不可协商约束

1. **先证明移动发生**。旧目录消失、新目录存在、全部文件哈希与移动前一致；不凭用户措辞假定已移动。
2. **0/0 不等于无需更新**。前缀为 0 只说明包内没有绝对路径；范围陈述与时态陈述仍要逐处审计。
3. **禁止机械替换**。把「用户级」一律改成「项目级」会破坏通用规则、双向对照示例与历史记录。每一处先分类再决定。
4. **历史陈述必须限时并补当前状态**。例：「该轮未移动」单独存在会被读成现状；必须写清是哪一轮，并在同文给出当前所在位置。
5. **只改过期项**。不改脚本逻辑、不改与位置无关的措辞、不顺手重写结构。
6. **以磁盘为准**。编辑前后记录 SHA-256；哈希漂移时先重读并合并，不覆盖并发改动。
7. **不执行未经确认的移动或复制**。本 Skill 审计迁移结果；目标位置由用户确认。
8. **不代用户执行斜杠命令**。`/skills reload` 与 `/skills list` 属于客户端命令；代理只能验证磁盘与运行时解析结果，不能宣称面板已刷新。

## 三种位置叙述

| 形态 | 例子 | 是否受前缀替换影响 |
|---|---|---|
| 路径前缀 | `C:\...\.qoder\skills\<name>` | 是，按前缀计数替换 |
| 范围陈述 | 用户级、项目级、本机、用户目录、仅当前项目可见、其他项目需另行安装 | 否 |
| 时态陈述 | 未移动、仍在、已不存在、现仅、该轮未移动 | 否 |

前缀计数与叙述审计必须分开做。`scripts/audit_relocation.py` 只负责计数与提示，分类与改写由人判断。

### 前缀四分支

| 旧 / 新前缀 | 含义 | 动作 |
|---|---|---|
| 旧 > 0，新 = 0 | 替换未执行或不完整 | 先补前缀；判为 `FAIL` |
| 旧 > 0，新 > 0 | 部分替换 | 逐文件重数，补全后再审计叙述 |
| 旧 = 0，新 > 0 | 已指向新位置 | 前缀无需改；叙述仍要审计 |
| 旧 = 0，新 = 0 | 包内无绝对路径 | **不得直接收工**；逐处审计范围与时态陈述 |

## 步骤

### 1. 证明移动已发生

```bash
test -d "<old-skill-dir>" && echo OLD_PRESENT || echo OLD_ABSENT
test -f "<new-skill-dir>/SKILL.md" && echo NEW_PRESENT || echo NEW_MISSING
```

- 旧目录仍存在：移动未完成，或用户描述的是计划。先报告实况，不继续改写。
- 新目录缺失：不要自行移动；请用户确认来源与目标。
- 在用户级与项目级 skills 根下搜索同名 SKILL.md，排除第二份副本。

### 2. 记录基线

```bash
py -3 "<this-skill-dir>/scripts/audit_relocation.py" "<new-skill-dir>" --old-prefix "<old-prefix>" --new-prefix "<new-prefix>" --old-dir "<old-skill-dir>"
```

`this-skill-dir` 是本 Skill 的安装目录，不是被迁移目录。记录：文件数与全部 SHA-256、每个文件的前缀计数、文档中的位置语句命中、`OLD_ABSENT`。移动尚未改写任何文件时，哈希应与移动前逐一相同。

若输出 `WARN ... normalized matches`，说明前缀写法与磁盘不一致（分隔符、盘符或大小写）；改用磁盘上的写法重跑，不能按 0/0 收工。

### 3. 分类每一处位置叙述

对每条命中标记一类：

- `STALE`：与当前磁盘矛盾。例如已移到项目级，却仍写「本机用户目录」或「未移动」。
- `VALID`：移动后仍成立。例如移到项目级后，「其他项目需另行安装」仍为真。
- `GENERIC`：规则或双向示例。例如「用户级对所有项目可见，项目级只在本项目可见」。

不要按词替换。`VALID` 与 `GENERIC` 保留原文；只改 `STALE`。

历史段落另加一条判据：是否限定了时间并给出当前状态。只写「未移动」而不说是哪一轮、也不写现在在哪，按 `STALE` 处理。

### 4. 审计 0/0 分支

前缀 0/0 时跳过替换，但继续以下检查：

- 逐条分类：用户级、项目级、本机、用户目录、项目目录、未移动、仍在、已不存在、仅当前项目、其他项目、可用范围、归属。
- 至少核对正文的「目标 / 何时使用 / Ressources」与证据文件的「状态 / 重新使用规则」是否仍描述当前位置。
- 在报告中写明「前缀 0/0，无替换；叙述审计 N 处，修正 M 处」。不得只写「无需更新」。

### 5. 最小改写

- 只替换被判定为 `STALE` 的句子或短语；保留周边结构与语气。
- 历史句改为限时表述，并补一句当前状态或指向当前状态的小节。
- 范围陈述改到与磁盘一致：用户级（所有项目可见）或项目级（仅本项目可见）。
- 改写后重跑步骤 2 的命令，确认没有引入新的前缀或路径。

### 6. 新路径验证

```bash
py -3 "<this-skill-dir>/scripts/audit_relocation.py" "<new-skill-dir>" --old-prefix "<old-prefix>" --new-prefix "<new-prefix>" --old-dir "<old-skill-dir>"
py -3 "<skills-root>/skill-file-qa/scripts/validate_skill.py" "<new-skill-dir>"
```

`skills-root` 是 skill-file-qa 的实际安装根；路径不确定时先列出用户级与项目级两个 skills 根确认。

- 审计脚本：`OLD_ABSENT`，旧前缀 0；`RESULT PASS` 或 `REVIEW`，退出码 0。
- `skill-file-qa`：`RESULT PASS`，0 fail；本地引用与跨 Skill 引用均能解析。
- 目标 Skill 有可执行入口时，用新绝对路径实跑一次，记录退出码；只做存在性检查不够。
- 检查新目录无缓存、无临时夹具；记录改写前后 SHA-256，未改的脚本哈希应不变。

### 7. 移动后可见性

按以下顺序验证，不要把三者混为一谈：

1. 磁盘：用户级与项目级 skills 根各列一次，确认旧位置消失、新位置存在。
2. 运行时：实际加载该 Skill，读取返回的 base directory 是否为新的绝对路径。
3. 客户端面板：`/skills reload` 与 `/skills list` 需用户自行在输入框执行；代理无法代跑，只能报告「未独立验证」。

来源会话中，磁盘与运行时解析均已指向新位置，而面板刷新仍未由代理验证。

### 8. 报告

给出移动前后位置、哈希一致性、前缀计数、叙述分类数量与修正清单、验证结果、未验证项。模板见下。

## 诊断

| 症状 | 原因 | 动作 |
|---|---|---|
| 前缀 0/0 后直接判定完成 | 把「无路径」当成「无叙述」 | 回到步骤 4，逐条分类范围与时态陈述 |
| 证据文件仍写「未移动」 | 该句不含路径，前缀 grep 抓不到 | 按 `STALE` 改写：限定轮次并补当前状态 |
| 机械替换后通用规则失真 | 把双向对照或规则示例当成迁移陈述 | 回退该处，标记为 `GENERIC` |
| 旧目录仍存在却报告移动完成 | 未先验证移动 | 停止改写，先报告 `OLD_PRESENT` |
| 移动后哈希变化 | 并发写入或复制不完整 | 停止编辑，重读并重新计数 |
| 旧前缀 0 但新前缀也 0，且包内确有绝对路径 | 路径写法不同、盘符大小写或转义不一致 | 看到 `WARN ... normalized matches` 就改用磁盘字符串重跑；不能按 0/0 收工 |
| `skill-file-qa` 报本地引用缺失 | 改写时引入不存在的相对路径 | 修正或改为纯文本描述 |
| 代理尝试执行 `/skills reload` | 斜杠命令属于客户端 | 交给用户执行并注明未验证 |
| 项目级目录存在但当前会话看不到 Skill | 运行时元数据或项目范围差异 | 列出两个 skills 根并实际加载 Skill 读取 base directory |

## 报告模板

```text
Skill : <name>
移动 : <old-skill-dir> -> <new-skill-dir>
移动证据: OLD_ABSENT, NEW_PRESENT, 哈希 N/N 一致
前缀 : 旧 X / 新 Y（0/0 时注明：无替换，叙述仍审计）
叙述 : STALE M 处已改；VALID N 处保留；GENERIC K 处保留
修正 : <file:line 摘要>
验证 : audit RESULT <PASS|REVIEW|FAIL> rc=<code>；skill-file-qa RESULT PASS
实跑 : <入口> rc=<code>（无入口则写 N/A）
哈希 : <file> <before> -> <after>；未改文件保持不变
可见性: 磁盘 <old absent/new present>；运行时 base=<path>；客户端面板 未独立验证
限制 : 复制场景 <已验证|未验证>；斜杠命令 未独立验证
```

## 完成定义

- [ ] 已证明移动发生：旧目录消失、新目录存在、哈希一致。
- [ ] 已记录全部文件哈希与前缀计数，并解释 0/0 的含义。
- [ ] 每条位置叙述都已分类为 `STALE`、`VALID` 或 `GENERIC`。
- [ ] 只改了 `STALE`；通用规则与双向示例未被机械替换。
- [ ] 历史陈述已限定轮次，并给出当前状态。
- [ ] 改写后已重跑审计，前缀计数未引入新命中。
- [ ] `skill-file-qa` 为 `RESULT PASS`，本地与跨 Skill 引用均可解析。
- [ ] 有入口脚本时已用新路径实跑并记录退出码。
- [ ] 可见性区分了磁盘、运行时与客户端面板三层状态。
- [ ] 报告中列出未验证项，未把面板刷新或复制场景说成已验证。

## Ressources

- `scripts/audit_relocation.py`：哈希、前缀计数、位置语句提示与迁移硬性检查，退出码 0/1/2。
- `references/preuve-session.md`：来源会话中 0/0 自移动、过期叙述原文与改写、可见性验证方式、脚本契约实测。
- `skill-absolute-path-references`：移动流程、前缀替换、哈希保持与存在性脚本。
- `skill-file-qa`：结构校验、本地与跨 Skill 引用解析。
- `skill-update-concurrency-safe`：目标目录预检、备份与并发哈希复核。
